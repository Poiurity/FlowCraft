# FlowCraft Closed-Loop Verify-Repair Agent System — Final Design

## 0. Grounding

### 0.1 What FlowCraft is today (verified against repo)

FlowCraft is an AI app builder: natural language → Flutter/Dart, via an intermediate JSON model **AppState**. OpenAI function-calling agents emit AppState; a deterministic ~1100-line TypeScript **CodeGenerator** turns AppState → a single `main.dart` string by pure string concatenation. A widget registry holds declarative `WidgetDefinition`s rendered by `renderFromDefinition()`. Sessions are an in-memory `Map`. The frontend previews via a DartPad iframe.

The pipeline is **open-loop**: agents generate, nobody verifies. This design converts it to a **closed loop**: generate AppState → render code → VERIFY → if errors REPAIR → re-render → re-verify (cap 2) → graceful degrade.

### 0.3 The hard constraint

No Dart/Flutter SDK is available in CI or on the server. Verification is **two layers behind one Verifier interface**:

- **Layer A "StaticValidator"** — pure TypeScript, ships now, catches structural error classes C1–C11 (extended through C14, plus C1-dotted) decidable without a compiler.
- **Layer B "RemoteAnalyzer"** — pluggable later (self-hosted dart-services over HTTP), env-gated dormant now; contract defined now so adding it is a registration, not a refactor.

**Honest interim guarantee (Layer A only):** "AppState internally consistent + references resolve + no unknown/known-bad widget classes reach codegen + no AppState-decidable compile break (poison widgets C11, unsupported/undeclared/duplicate-method actions C3b, member-access bindings C1-dotted-as-C1, duplicate identifiers C12) survives to SUCCESS" — **not** "always compiles" (that needs Layer B). Residual risk: **N1** nonexistent widgets (the `datePicker→DatePicker` poison), **N2** constructor signature mismatch, **N3** Dart type mismatch (incl. unverifiable member access behind C1-dotted warnings), **N4** Flutter API misuse.

## 1. Verification Strategy (Layer A / Layer B)

**Unifying principle for Layer A:** a StaticValidator error class may only fire on a symbol/prop that codegen **actually emits**, evaluated on the **post-sanitize, post-merge** AppState (§6.0). Validating a prop codegen ignores (false positive) and missing a never-declared-method emission (false negative) are equally fatal, because the RepairAgent is driven by these error contexts. Every C-class below is pinned to a verified codegen emission site.

**Placement invariant (authoritative, §6.0/§9):** the validator runs on the object `codeGenerator.generate()` consumes — the parse output of the sanitization pipeline on the live path, or the bare `AppStateSchema.parse` output on the import path — byte-for-byte the same reference, never on raw agent output. Two corollaries (§9):
- **Corollary A (live path).** Any throw *before* the merge completes (e.g. `enforceSingleScreen` L284, §9.1) is upstream of RENDER and VERIFY — the Verifier cannot see it. It is owned by the `run()` exception contract (§6.5/§9.1), not the C-rules.
- **Corollary B (import path).** Sanitize is bypassed, so C-classes the live path pre-closes (C9, C3-navigate, the blank-type variant of C5/C10, multi-screen) become reachable. The import handler is the validator's primary exposure surface and a first-class call site (§9.2).

Fixtures and reachability follow §6.0.2/§9.2.4.

### 1.1 One Verifier interface, two implementations, one composite

```ts
// services/verification/types.ts  (shared by both layers — single source of truth)
interface Verifier {
  verify(appState: AppState, code: string, ctx: VerifyContext): Promise<AnalyzeResult>;
  isAvailable(): boolean;
}

interface VerifyContext {
  registryVersion: string;            // definitions-only hash (§2.6), for prompt cache-bust + telemetry
  registrySnapshot: RegistrySnapshot;  // frozen read-only facade (§6.1); same object RENDER used
  source?: 'live' | 'import';          // §6.0.1/§9.2 — drives reachable-class expectations + repair gating
  requestId?: string;
  attempt?: number;
}

interface AnalyzeResult {
  ok: boolean;                 // errors.every(e => e.severity !== 'error')
  errors: ValidationError[];
  warnings: ValidationError[];
  source: 'static' | 'remote' | 'composite' | 'cache' | 'static-only-degraded';
  cacheKey: string;
  fromCache: boolean;
  durationMs: number;
}

interface SourceLocation {
  line?: number;               // 1-based (dart-services convention; reused by Layer A where available)
  column?: number;
  offset?: number;
  length?: number;
  screenId?: string;
  nodePath?: NodePath;         // positional addressing into the AppState (see §2.3)
}

interface ValidationError {
  code: string;                // 'C1'..'C14', 'C1-dotted', 'C3b-collision', 'P1'..'P7', 'B-<dartcode>', 'D0', 'W-leading'
  severity: 'error' | 'warning';
  message: string;
  source: 'static' | 'remote' | 'orchestrator';
  location?: SourceLocation;
  context?: Record<string, any>;
}
```

`AnalyzeResult.ok` is defined identically across all layers: **no `errors` of `severity === 'error'`**. Warnings never set `ok=false`, never feed RepairAgent, never burn an LLM call. Every `ValidationError.location.nodePath` is **load-bearing** for the RepairAgent's `editablePaths` bounding (§2.2 / §6.10).

### 1.1a RegistrySnapshot — the frozen registry facade (§6.1)

`VerifyContext.registrySnapshot` is **NOT a `Map`**. It is a frozen read-only facade unifying the three access shapes the design references (`values()`, `hasWidget()`, `getDefinition()`):

```ts
export interface RegistrySnapshot {
  values(): IterableIterator<WidgetDefinition>;   // registry-defined only; for version hash & C7/C8/C11
  hasWidget(type: string): boolean;               // mirrors hasWidget: HARDCODED_WIDGETS ∪ registry keys
  getDefinition(type: string): WidgetDefinition | null; // registry-defined only; null for hardcoded & unknown
  readonly hardcodedWidgets: ReadonlySet<string>; // the compiled-in 15, exposed for C5/lockstep
  readonly registryVersion: string;               // sha256(stableStringify([...values]))[:12]
}
```

Constructed by a new `WidgetRegistryManager.cloneDefinitions(): RegistrySnapshot` (§6.1): `deepFreeze(structuredClone(...))` of each def (immune to later `addDefinition`/`stageDefinition` mutation), version hash over definitions only, `hardcodedWidgets = HARDCODED_WIDGETS` (now exported from `registry-manager.ts` L7). **The frozen clone — not the live manager — is the only registry the validator and the cache key see**, preserving determinism across concurrent registry mutations.

> **Resolution of the §9.2.2 alternative.** §9.2 proposed `cloneDefinitions(): ReadonlyMap` + a separate `registryVersion(): string`. This is **superseded** by the `RegistrySnapshot` facade, which is the established cross-section contract (used by StaticValidator, CompositeVerifier, the cache key, and the import handler alike). The §9.2.2 `registryVersion()` **content-hash logic is retained as the facade's `registryVersion` implementation**: a sha256 over the canonical (name-sorted) serialization of all defs, truncated to 12 chars — a *content* hash (not a monotonic counter) so identical registry content yields an identical key across server restarts, preserving cache validity. The import handler builds its context from `widgetRegistry.cloneDefinitions()`, never from a bare Map (§9.2.3 reconciled).

### 1.2 Layer A — StaticValidator

```ts
// services/verification/static-validator.ts
export class StaticValidator implements Verifier {
  isAvailable(): boolean { return true; }   // ships now, no SDK
  async verify(appState: AppState, code: string, ctx: VerifyContext): Promise<AnalyzeResult>;
}
```

`code` is accepted to satisfy the interface but Layer A inspects `appState` only — codegen already proved it produced a string; structural errors live in the model. **The validator reads `ctx.registrySnapshot` (the RAW, un-audited registry facade)** — the exact same object RENDER used — so C5/C11 see identical registry state to codegen and the datePicker poison def is visible to C11. `source: 'static'`.

#### 1.2.1 Single-pass traversal with a scope frame

One DFS over the whole AppState accumulates errors. The walker mirrors `collectActions`/`countWidgets` (children **and** props-embedded nodes) but threads a `Frame` so item-scope (C4) and `nodePath` are computable in the same pass.

```ts
interface Frame {
  screen: Screen;
  varNames: Set<string>;
  varByName: Map<string, StateVariable>;
  inItemScope: boolean;            // true ONLY inside a dataSource-bearing listView's template
  dataSourceList: string | null;   // the dataSource var name when inItemScope
  itemFields: Set<string> | null;  // computed by itemFields(listVar) — §6.0.6
  declaredHandlers: Set<string>;   // from declaredHandlerMethods (§6.0.5)
  handlerCollisions: Set<string>;  // duplicate-name methods (§6.0.5) → C3b-collision
  nodePath: NodePath;
  parentType: string | null;       // for C6 flex-structure checks
}
```

**nodePath** is positional (AppState nodes have no IDs; only `Screen` has `id`): `screens[0].body.children[1].props.title`, `screens[0].screenState.variables[2]`. Built by appending `.children[i]` / `.props.<k>` on descent. Grammar/resolver shared with the RepairAgent via `node-path.ts` (§2.3 / §4.4) so the two sides never drift.

**Item-scope tracking (C4):** `inItemScope` opens **only** under a `listView` whose `props.dataSource` is set (codegen L797-809). Template = `props.itemBuilder` if present else `children[0]`. Recurse into the template with `inItemScope=true`, `dataSourceList` set, `itemFields = itemFields(listVar)` (§6.0.6 algorithm). A **static** listView recurses with `inItemScope=false` **explicitly**. Nested dataSource listViews re-open a fresh item scope.

**Pre-pass per screen (handler oracle):** before walking, compute `{declared, collisions} = declaredHandlerMethods(screen, vars)` (§6.0.5) — the exact set of method symbols `generateActionHandlers` will emit (dedup-key-deduplicated, gate-filtered) plus the same-name/different-`K` collision set — and store on the frame. This is the membership oracle for C3b.

**Walk skeleton:**
```
validateScreen(screen, idx):
  {declared, collisions} = declaredHandlerMethods(screen, vars)  // §6.0.5
  frame = makeFrame(screen, declared, collisions, nodePath="screens[idx].body")
  walk(screen.body, frame)
  checkAppBarActions(screen, declared, frame)            // C3b appBar (inItemScope=false)
  validate fab.action with frame
  emit C3b-collision for each name in collisions
  if screen.appBar?.leading present: emit W-leading warning (NOT walked as a C3/C4 site)

walk(node, frame):
  classifyNode(node, frame)         // C5, C7, C8, C11, C6-self
  validateNodeBindings(node, frame) // C1, C1-dotted, C2, C3 (incl. C3b), C4, C13
  childFrame = frame
  if node.type==='listView' && node.props.dataSource:
       childFrame = { ...frame, inItemScope:true, dataSourceList, itemFields }
  else if node.type==='listView':
       childFrame = { ...frame, inItemScope:false }     // explicit: close item scope
  for (k, v) in sortedKeys(node.props) where isWidgetNode(v):
       if node.type==='listView' && k==='itemBuilder': continue
       walk(v, descend(childFrame, `.props.${k}`))
  if node.type==='listView' && node.props.dataSource:
       template = node.props.itemBuilder ?? node.children?.[0]
       if template: walk(template, descend(childFrame, template-path))
       else: emit C6 listViewNoTemplate
  else:
       for i, child in node.children: walk(child, descend(childFrame, `.children[${i}]`))
```

Actions extracted per-node from the exact prop keys codegen reads: `action, onToggle, onDismissed, onTap, onSubmit`, plus `fab.action` and `appBar.actions[].action`. **`appBar.leading.action` is NOT extracted** (phantom site). Each extracted action runs through C3.

**Determinism:** errors emitted in deterministic order — screens by index, DFS children before props-embedded nodes, `Object.keys(props)` **sorted** before iterating embedded nodes. The error multiset is stable, which both the oscillation guard and `cacheKey` depend on.

#### 1.2.2 Error classes C1–C14 (+ C1-dotted, C3b-collision)

All contexts share base `loc = { screenId, screenName, nodePath, widgetType }`; below lists extra fields only. **All predicates evaluate on the post-sanitize AppState (§6.0).** The **Live / Import reachability** column is authoritative per the §6.0.2/§9.2.4 matrix and drives fixture tagging.

| C-class | Live path | Import path |
|---|---|---|
| C1, C1-dotted, C2, C3 (non-navigate), C3b, C4, C6, C7, C8, C11 | Reachable | Reachable |
| **C5** | Reachable for *wrong-but-present* types; blank type masked (sanitizeWidget L88 → `sizedBox`) | Fully reachable (incl. blank/`DatePicker`-style types) |
| **C3-navigate** | **UNREACHABLE** (stripNavigateActions) | Reachable |
| **C9** (nav integrity + PascalCase) | **UNREACHABLE** (enforceSingleScreen + name PascalCase) | Reachable (primary path) |

- **C1 undeclared-state-var-ref** (error). A prop/action field that becomes `_<name>` references a name not in `frame.varNames`. Candidates: `boundTo`, action `fieldName/listName/valueFrom`, `clearFields[]`, `itemTemplate` `{{var}}`, and bare-non-`item` text bindings (step 4 of the binding cascade). Context: `{ refName, refKind, availableVars, suggestion?: nearestKnown(refName, varNames) }`.

- **C1-dotted member-access binding** (predicate on the raw binding, §6.0.4/§9.3). A text binding `{{x.y}}` where `head !== 'item'` AND the inner expression `includes('.')` (codegen L547 emits `${_x.y}` — member access on state var `_x`). **Predicate (the §9.3 correction, defined on the binding expression, L547 is corroboration only):** for each `{{ expr }}`, `head = expr.split('.', 1)[0]`; **flag C1-dotted ⟺ `head !== 'item'` AND `expr.includes('.')`**. The `item.`-family (head === `'item'`) is the *only* dotted form codegen handles correctly (L546) and is governed by C4 instead — keep the two rules disjoint by the `head === 'item'` discriminator so a binding is never double-flagged.

  **Severity — graduated (resolution of the §9.3-vs-vPrev contradiction):** C1-dotted is a **`warning` by default, escalating to a C1 `error` only when `head` is an undeclared state var.** Rationale: Layer A *can* prove `_x` is undeclared (that is a genuine C1 compile break), but **cannot** prove that member access `.y` on a *declared scalar* `_x` fails — FlowCraft state vars are scalars/lists with no members, so `_order.total` is almost certainly an N3 type error, but the *true compile verdict* needs the Dart front-end (Layer B). Emitting a hard `error` on the shape alone would assert a compile failure Layer A cannot decide, violating the honesty boundary that §1.5/§8.2 commit to ("C1-dotted is a *warned*, not closed, N3 surface"). The §9.3 shape-based predicate is adopted; its blanket-`error` severity is **not** — the head-declared case stays a warning Layer B promotes to `B-` later. Context: `{ rawExpr, head, emitted: '_x.y', headDeclared: boolean }`. Message: `` Binding `{{x.y}}` compiles to member access `_x.y` on state var `_x`. FlowCraft state vars have no members; this likely fails the Dart analyzer (Layer B). If `_x` is undeclared this is a hard error. ``

  **Binding classification cascade (the single authority for C4-vs-C1 — §6.0.4/§9.3, mirrors codegen `if` order exactly):**

  | Step | Condition on trimmed inner expr | Class | Authority |
  |---|---|---|---|
  | 1 | `=== 'item'` | item-whole (C4 scope) | L545 |
  | 2 | `startsWith('item.')` | item-field (C4: field ∈ `itemFields`, §6.0.6) | L546 |
  | 3 | `includes('.')` (head ≠ item, excluded by 1–2) | **C1-dotted** (warn; C1 error if head undeclared) | L547 |
  | 4 | else | **C1** (error if head undeclared) | L548 |

  No C-rule defines its dotted/item predicate independently; all reference this table. **L547 and L548 are byte-identical** — the cascade distinguishes on the *input string*, not on codegen branches.

- **C2 dangling dataSource** (error). `listView.dataSource` / action `listName` names a var that's missing or not `stringList|itemList`. When C2 fires for a name+node, the parallel C1 for the same `(refName, nodePath)` is **suppressed**. Context: `{ refName, dangling:'missing'|'wrongType', actualType?, expected:['stringList','itemList'], listVarsAvailable }`.

- **C3 action integrity — sub-rules** (error), enum-complete over all 10 `Action` members. Evaluated per action reachable from props action sites + `fab.action` + `appBar.actions[].action` (**never** `appBar.leading.action`):
  - **C3a referential.** `addItem` → `listName ∈ screenState` (`stringList|itemList`; if `itemList`, `itemTemplate` present); `removeItem` → `listName ∈ screenState`; `toggleItemField` → `listName ∈ itemList` AND `fieldName ∈ that list's itemFields`; `increment/decrement` → `fieldName ∈ screenState` (`int|double`); `navigate` → `target` resolves (C3 owns var refs, C9 owns route integrity) — **live-path UNREACHABLE (stripped by `stripNavigateActions`), import-only**; `pop`/`none` → **no referential obligation**.
  - **C3b undefined/duplicate handler-method.** Trigger surface: **any mutating action emitted at a site not reachable by `generateActionHandlers`, or whose emitted method name collides**. Checked against the §6.0.5 oracle (`declared` + `collisions`):
    1. **`setValue`/`clearField` anywhere** — `generateActionHandlers` emits no branch (L301-392), `actionExpression` emits the bare symbol → undefined method.
    2. **`appBar.actions[].action` of any mutating/index type** — `collectActions` never descends into `appBar`; for index types a free `index` is also referenced (double break).
    3. **Gated-addItem body sites** — `addItem` collected from `body` whose body codegen gates out at L311 (e.g. `itemList` without `itemTemplate`) → dangling call.
    4. **C3b-collision** (§6.0.5) — two emitted actions with identical `actionMethodName` but distinct dedup `K` → duplicate Dart method definition.

    **Algorithm (the §6.0.5 oracle — bug-for-bug mirror of codegen's collect → dedup → per-type gate):**
    ```ts
    // services/codegen-shared/action-naming.ts  (imported by codegen AND validator)
    //   actionMethodName(a) [L420-425], collectActions(node) [L397-418], INDEX_REQUIRED [L962]

    function declaredHandlerMethods(screen, vars): { declared: Set<string>; collisions: Set<string> } {
      const actions = collectActions(screen.body).concat(screen.fab?.action ? [screen.fab.action] : []);
      const emittedByDedup = new Map<string, Action>();           // first-seen per K wins (L299-304)
      for (const a of actions) {
        if (!a || a.type==='navigate' || a.type==='pop' || a.type==='none') continue;  // L302
        const k = `${a.type}_${a.listName||''}_${a.fieldName||''}_${a.valueFrom||''}`;  // L303
        if (emittedByDedup.has(k)) continue;                       // L304 (no body)
        if (!bodyWouldEmit(a, vars)) continue;                     // per-type gate, below
        emittedByDedup.set(k, a);
      }
      const nameCount = new Map<string, number>(), declared = new Set<string>();
      for (const a of emittedByDedup.values()) {
        const n = actionMethodName(a);
        nameCount.set(n, (nameCount.get(n)||0)+1); declared.add(n);
      }
      const collisions = new Set([...nameCount].filter(([,c])=>c>1).map(([n])=>n));
      return { declared, collisions };
    }

    // bodyWouldEmit mirrors the per-type emission guards so the oracle never declares
    // a symbol codegen didn't emit:
    //   addItem        → listVar.type==='itemList' && itemTemplate  (L311)  OR  listVar.type==='stringList' (L345)
    //   removeItem     → listName present (L361)
    //   toggleItemField→ listName && fieldName present (L370)
    //   increment      → fieldName present (L379)
    //   decrement      → fieldName present (L386)
    //   setValue/clearField → FALSE (no case in L301-392) → never declared → always C3b
    ```
    Body/fab sites: a mutating action whose `actionMethodName(a) ∉ declared` → C3b (undefined method); `∈ collisions` → C3b-collision. AppBar sites (`checkAppBarActions`) check `∉ declared`, with an extra "references undefined `index`" note for index types. `context.methodName === actionMethodName(a)` is **symbol-equal** to codegen's call-site emission in every case. **Design decision (chosen): validator-rejects.** TODO anchors: `code-generator.ts:392` (deferred setValue/clearField handler impl) and the appBar emission site L1004 (deferred "collect appBar actions"). Context: `{ actionType, problem, methodName, indexInjected?, collision? }`.
  - **C3c index-scope.** `removeItem`/`toggleItemField` require `inItemScope` — overlaps C4 (C4 owns the message; C3 cross-references).

- **C3-phantom / W-leading dead-prop** (warning, `W-leading`). If `screen.appBar.leading` is present at all, emit one warning: `appBar.leading is ignored by codegen; remove it.` The validator MUST NOT walk `leading.action` for C3/C4 (a C3 error here would drive the RepairAgent to "fix" a no-op prop). Making `leading` a real rendered site is a codegen+schema change, deferred.

- **C4 item-field binding / index-action outside scope** (error). `boundToItemField`, `conditionalDecoration.field`, text `{{item}}`/`{{item.field}}` (cascade steps 1–2), or index-taking actions used while `inItemScope===false`. C4 walks **prop-embedded** action sites (`props.onDismissed/onToggle/onTap` on listTiles) — mirroring `collectActions`. Inverse: `inItemScope===true` and referenced field ∉ `itemFields` → `problem:'unknownItemField'`.

  **itemFields resolution (the §6.0.6 algorithm — mandatory gate):** computed once per screen, screen-wide, keyed on `listName === dataSource var`:
  ```
  itemFields(listVar):
    if listVar.type !== 'itemList': return ∅           // mirrors L311 gate — stringList contributes NO fields
    fields = ∅
    for a in collectActions(screen.body) ++ (fab.action ? [fab.action] : []):
        if a.type==='addItem' && a.listName===listVar.name && a.itemTemplate:  // gating condition
            fields ∪= keys(a.itemTemplate)             // codegen adds these keys (L315-318)
    fields ∪= (listVar.itemFields ?? []).map(f => f.name)
    return fields
  ```
  Because codegen's `_tasks.add({...})` is global to the screen state, an `addItem{listName:'tasks'}` anywhere contributes its template keys to *every* `listView` bound to `tasks`. The `type==='itemList'` gate is mandatory — omitting it over-populates the set (a `stringList` `addItem` contributes nothing, L345) and misses genuine C4 errors. `sanitizeStateVariables` (base-agent L77-80) coerces the *declared* `itemField.type`, never the `addItem.itemTemplate` keys, so the union basis is the templates (the codegen source of truth). A `{{item.x}}` outside any listView item template is a C4-scope-error regardless of fields. Context: `{ binding, fieldName?, problem:'outsideItemScope'|'unknownItemField', enclosingListDataSource?, knownItemFields? }`.

- **C5 unknown widget type** (error). Predicate (exact, §6.0.3): `isRenderable(type) := SWITCH_CASES.has(type) || ctx.registrySnapshot.getDefinition(type) !== null`; **C5 fires ⇔ `!isRenderable(node.type)`** (equivalently `!ctx.registrySnapshot.hasWidget(node.type)`, the hardcoded-15 ∪ registry defs). On the **live path** typeless nodes were already coerced to `sizedBox` (base-agent L88), so C5 fires only for *non-empty unknown* types; on the **import path** the full surface (e.g. `type:"DatePicker"`) is reachable (§6.0.2/§9.2.4). When C5 fires, **skip C7/C8/C11 and binding checks on that node**. `datePicker` does **not** trigger C5 (def exists → `hasWidget===true`). C5 **upgrades codegen's silent `SizedBox.shrink()` degrade (L472) to an error** — load-bearing if Option B drops the tool-schema enum (§5.3). Context: `{ unknownType, renderedAs:'SizedBox.shrink', suggestion?: nearestKnown(node.type, allKnownTypes), allKnownTypes }`.

- **C6 unbalanced/malformed structure** (error; empty-flex warning). Mirrors codegen's auto-wrap/auto-unwrap via the shared `flex-rules.ts` predicate (§6.9) to avoid false positives. Fires only on the *unfixed residue*: an `expanded`/`spacer` whose structural parent is neither a Flex (codegen would `wouldWrapInExpanded`) nor a single-child unwrapping slot (codegen would `wouldUnwrap`) — e.g. an `expanded` as a static `listView` child (L820, no unwrap). Does **not** fire where `wouldWrapInExpanded` returns true (bare `listView` in a `Column`). Sub-rule: `listView` with `dataSource` but no `itemBuilder`/`children[0]` → `listViewNoTemplate`. **Parity guarantee:** the flex decision logic lives in `flex-rules.ts` imported by **both** CodeGenerator and StaticValidator. Context: `{ problem, parentType?, dataSource? }`.

- **C7 malformed registry definition** (error). The `WidgetDefinition` a node reaches is invalid for `renderFromDefinition`: `dartWidget` non-empty; each `props[].type ∈ {number,string,bool,color,icon,edgeInsets}`; `dartParam` a string; `stateBinding` has `valueProp`+`onChangedProp`. Deduped by def.name. Context: `{ defName, problem, detail }`.

- **C8 prop-value plausibility** (warning; error only for invalid-Dart-identifier icons). Shares codegen resolvers (no duplication, §9.4): color props via `colorIsPlausible` (imports the verbatim named-color map `NAMED_COLORS` from `color-table.ts`, plus the **two anchored hex regexes `HEX6`/`HEX8` — NOT a `{6,8}` quantifier**) — miss → **warning** (codegen degrades to `Colors.blue`). The canonical C8-color warning is a **7-char hex** (`#abcdef0`): codegen silently downgrades it to blue (L1031), and the shared `colorIsPlausible` returns `false` for exactly-7. Icon props via `KNOWN_ICONS` membership (`known-icons.ts`, ~80 identifiers) — unknown-but-valid-identifier → **warning** (N4 surface); invalid Dart identifier → **error**. Number/size props must be finite. Context: `{ propName, propValue, expectedType, problem, suggestion?: nearestKnown(value, pool), fallbackUsed? }`. (Full mirror logic §9.4.)

- **C9 navigation integrity + Dart PascalCase** (error; **IMPORT-PRIMARY**). `navigate.target`/`initialRoute`/`bottomNavItems[].screenId` must resolve; `screen.name` must match `^[A-Z][A-Za-z0-9]*$` and be unique. **Reachable essentially only via the import path**: the live path forces `navigation={stack,/}`, single-screen, and PascalCases names (`enforceSingleScreen` structure-agent L284-285 + `sanitizeScreens` base-agent L54-57), so no C9 trigger survives to live VERIFY — tag all C9 fixtures `import-only`. Context: `{ problem, value, availableRoutes?, availableScreenIds?, screenId? }`.

- **C10 Dart reserved-word / invalid-identifier collisions** (error; **partially live-reachable**). `screen.name`, state var names, item-field names checked against `DART_RESERVED`/`DART_BUILTIN`/`DART_CORE_COLLISIONS` and `^[a-zA-Z_][a-zA-Z0-9_]*$`. Reserved-word *content* (e.g. a var named `class`) survives the live name-stripping (base-agent L54, which strips non-alphanumerics but does **not** reject reserved words) → reachable both paths; non-Pascal/punctuated *screen names* are erased on the live path → that sub-case is import-only. **C10 needs two fixtures**: a `class`-named-var fixture (`live`) and a non-Pascal/punctuated screen-name fixture (`import-only`). Context: `{ identifier, kind, problem }`.

- **C11 dartWidget not on allowlist (anti-poison)** (error). Predicate (keyed **strictly on `def.dartWidget`**): for each node `n` where `!snapshot.hardcodedWidgets.has(n.type)` **and** `snapshot.getDefinition(n.type)` is non-null, check `KNOWN_FLUTTER_WIDGETS.has(def.dartWidget)`; absent → emit. Hardcoded-15 types are trusted/skipped (compiled-in via L454-468; carry no `dartWidget`). **This is the gate that catches `datePicker→DatePicker`** (registry.json L181-182), path-independent (registry-load-time → reachable both paths). Context: `{ defName, dartWidget, problem:'notAKnownFlutterWidget', allowlistVersion }`. Frozen allowlist in §2.4.

- **C12 duplicate identifier (composed/multi-screen only)** (error). Two screens share `id`, `route`, or Dart class `name` → duplicate `class` in generated Dart. Runs in the composed pass (§7); on the import path it can also fire on a multi-screen import.

- **C13 customCode stateDeps resolution (Phase 5 only)** (error). A `customCode` node's `interface.stateDeps ⊄ screen.screenState.variables`. The only thing Layer A can assert about a customCode node.

- **C14 customCode-present-but-disabled** (warning). A `customCode` node exists while the gate is closed → makes the `SizedBox.shrink()` degrade visible.

**Cascade suppression & ordering** (determinism): C2 suppresses parallel C1; C5 suppresses C7/C8/C11 on the same node; C4 and C1/C1-dotted are disjoint by the §6.0.4 head-token cascade. **Top-N ordering for RepairAgent**: C9/C10/C11/C12/C3b/C3b-collision (compile-fatal) > C1 (incl. | dart `kind` | severity | effect |
|---|---|---|
| `error` | `error` | fails `ok`; triggers REPAIR |
| `warning` | `warning` | recorded, never blocks |
| `info` | `warning` | recorded, never blocks |

(Try changing the name...)" }`. Closes N1/N2 (Layer A's C11 already catches this poison pre-codegen). Member-access bindings behind C1-dotted warnings (N3) become hard `B-` errors here.

### 1.4 CompositeVerifier — the object the Orchestrator holds

```ts
export class CompositeVerifier implements Verifier {
  constructor(private staticV: Verifier, private remoteV: Verifier, private cache: VerificationCache) {}
  isAvailable(): boolean { return true; }   // composite always available (A always is)
  async verify(appState, code, ctx): Promise<AnalyzeResult>;
}
```

1. **Cache check** by the composite `cacheKey` (§6.0.7). Hit → return `fromCache:true`.
2. **Layer A always runs** (pure TS, sub-ms).
3. **Short-circuit:** run Layer B **only if** `a.ok && remoteV.isAvailable()`. If A found errors, those go to REPAIR first; the repaired code re-enters `verify` and B runs then (also prevents noisy compiler cascades).
4. **Merge** A+B, dedup by `${severity}|${code}|${line}|${column}|${message}` (disjoint namespaces; on equivalent-class collision keep the registry-aware Layer A instance). Sort: errors before warnings, then `location.line`, then `code`.
5. **Cache** the merged result unless `source==='static-only-degraded'`.

| A.ok | B available | result `source` |
|---|---|---|
| cache hit | — | (cached) `fromCache:true` |
| false | * | `static` (→ REPAIR; B runs next round) |
| true | false | `static` |
| true | true | `composite` |

### 1.5 What is claimable

- **Layer A only (ships now):** internally consistent + references resolve + no unknown/known-bad widget classes reach codegen + no AppState-decidable compile break survives to SUCCESS (C11 poison, **C3b undeclared/duplicate/unsupported actions** incl. appBar/gated-addItem/collision, C12 duplicate identifiers, C9/C10 identifier integrity *on the import path* / C10-content live). **N1–N4 remain open** beyond the specific decidable cases; C1-dotted member access is a *warned*, not closed, N3 surface.
- **With Layer B live (A→B composite):** the emitted `main.dart` passes the Dart analyzer for every SUCCESS — closes **N1, N2, N3** (incl. C1-dotted member access) and the analyzer-detectable subset of **N4**. Still **not claimable / blocked-on-B-runtime:** runtime behavior (null-deref, overflow, async) and semantic intent fidelity (the Critic, §6).
- The composite claim holds **only while the breaker is closed**; when B is degraded, the guarantee transparently falls back to the Layer-A claim. Telemetry (`verify.source`, `remote.ran`/`remote.degraded`) is the source of truth.

### 2.6 VerificationCache + registryVersion + the composite cache key

```ts
export class VerificationCache {
  constructor(maxEntries = 256);
  get(key): AnalyzeResult | undefined;             // LRU move-to-MRU; returns {...hit, fromCache:true}
  set(key, value): void;                            // evict oldest over cap
  getStats(): CacheStats;
}
```

Module-level singleton, process-lifetime, content-addressed (no TTL). `stableStringify` (recursive key-sort) is required because agent outputs lack stable key order.

**`registryVersion`** (definitions-only) is derived: `sha256(stableStringify([...snapshot.values()]))[:12]`, **computed once per request** over the frozen snapshot (in `prepare()` on the live path; inline via `cloneDefinitions()` on the import path, §9.2.3). It is a **content** hash (not a counter) so identical registry content yields the same key across restarts. Used for **prompt cache-busting and telemetry**, and carried on `VerifyContext`.

**The VerificationCache key is a COMPOSITE (§6.0.7 — corrects vPrev's registryVersion-only formula), folding everything a verify result depends on:**

```ts
const KNOWLEDGE_VERSION = sha256(stableStringify({
  knownFlutterWidgets: [...KNOWN_FLUTTER_WIDGETS],  // C11
  namedColors: NAMED_COLORS,                        // C8 color (L1035-1056)
  knownIcons: [...KNOWN_ICONS],                     // C8 icon
  dartReserved: [...DART_RESERVED],                 // C10
  hardcodedWidgets: [...HARDCODED_WIDGETS],         // ← the 15, MISSING from registryVersion
})).slice(0,12);

const CODEGEN_VERSION   = '<git-sha-or-manual-bump>';   // bumped on any code-generator.ts / flex-rules.ts / color-table.ts edit
const STATIC_VALIDATOR_VERSION = '<bump>';              // bumped on any C-rule logic change

cacheKey = sha256(stableStringify({
  appState,                                  // post-sanitize, post-merge (§6.0)
  registryVersion: snapshot.registryVersion,
  knowledgeVersion: KNOWLEDGE_VERSION,
  codegenVersion: CODEGEN_VERSION,
  validatorVersion: STATIC_VALIDATOR_VERSION,
})).slice(0,16);
```

Rationale: `registryVersion` alone hashes only registry-defined values — a change to `known-icons.ts`, the color table, `dart-reserved`, `HARDCODED_WIDGETS`, or the shared codegen modules would NOT change it, serving stale results after a validator/codegen change. The composite is the **single authoritative cache key**; it is frozen for the whole request (snapshot frozen in `prepare()`), so `cacheKey` is stable across all repair attempts and the oscillation guard's "identical (state,version) ⇒ identical verify result" invariant holds. Never cache `static-only-degraded`. Owned by the CompositeVerifier.

## 3. Phased Plan (no-Dart recalibrated)

### 3.0 Orchestrator seam — three-function split

The orchestrator loop is a **wrapper, not an in-place rewrite** of `Orchestrator.process()`. The seam is a **three-function split**, with EXTEND hoisted **out** of the re-runnable region so the registry version is frozen for the whole request:

```ts
// prepare(): runs ONCE per /generate. Owns Clarify + Extend + snapshot. NOT re-run on repair.
async prepare(prompt, currentState?): Promise<PrepareResult>;
//   PrepareResult { clarified, intent, baseState: currentState, registrySnapshot, registryVersion }
//   1. clarified = clarifier.clarify(...)
//   2. await widgetExtender.ensureWidgets(clarified.requiredWidgets)   ← the ONLY EXTEND; stageDefinition (§4.5), no persist
//   3. registrySnapshot = widgetRegistry.cloneDefinitions()            ← frozen facade (§6.1)
//   4. registryVersion = registrySnapshot.registryVersion             (definitions-only, computed ONCE)

// generateForIntent(): the intent switch. Re-runnable. Pure w.r.t. the registry (reads snapshot only).
async generateForIntent(ctx: PrepareResult, repairFeedback?): Promise<AppState>;
//   switch(ctx.intent){ create → structure.generate + design.generate; modify* → .modify(...) }
//   NOTE: structure.generate/modify run sanitizeScreens (base-agent) + enforceSingleScreen (structure-agent)
//         internally — the placement boundary (§6.0.0) is INSIDE this call. enforceSingleScreen MAY THROW
//         StructureEmptyError (§9.1) — caught by run() (§6.5/§9.1.2), classified to degrade-prior vs 500.

// merge() (the AppStateSchema.parse boundary) stays private and runs on every produced AppState.
```

`generateForIntent` dispatches by `ctx.intent` identically each call. **Ordinary repair (attempts 1..N) goes through RepairAgent** (cheap, targeted patches); `generateForIntent` is re-invoked **only** as the last-resort full-regenerate tier and for Critic reloop. Because EXTEND ran once in `prepare()` and the loop reads `ctx.registrySnapshot`, the registry cannot change between attempts → `cacheKey` stability and oscillation invariants hold.

### 3.1 Loop states & caps

`CLARIFY → EXTEND → GENERATE → RENDER → VERIFY → (SUCCESS | REPAIR | DEGRADE)`, with the Critic (§6) inserting `CRITIC/RELOOP` after a passing VERIFY.

| Cap | Value | Enforced |
|---|---|---|
| Repair iterations | `MAX_REPAIRS = 2` (≤3 VERIFY passes) | before REPAIR |
| Wall-clock | `WALL_CLOCK_MS = 30_000` | before each LLM call |
| Oscillation | error-multiset key returns to a prior set | `seen.has(curKey)` |
| Progress | identical error set across iterations | `curKey === prevKey` |
| Unrepairable | RepairAgent flag | `repair.unrepairable === true` |
| Critic reloops | `MAX_CRITIC_RELOOPS = 1` | attempt index |

Wall-clock guard: `if (elapsed + PER_REPAIR_BUDGET_MS(9000) > WALL_CLOCK_MS) degrade('wall_clock')`.

### 3.2 Multiset / progress / oscillation primitives

```ts
function multiset(errors): Record<string,number> {            // severity==='error' only, keyed by (code, location)
  const m={}; for(const e of errors) if(e.severity==='error') m[msIdent(e)]=(m[msIdent(e)]??0)+1; return m;
}
function msKey(errors){ const m=multiset(errors); return Object.keys(m).sort().map(k=>`${k}:${m[k]}`).join('|'); }
```

`msIdent(e)` = `${e.code}@${e.location?.nodePath ?? ''}` (location-aware so A→B→A is detectable even when counts match — the §6.0.8 `errorSignature`). The guard uses `msKey`.

### 3.3 Main loop (the §6.0.8 seeded guard — corrects vPrev's off-by-one)

```ts
async run(prompt, currentState?): Promise<LoopResult> {
  const t0=now(), requestId=randomUUID();
  // EXCEPTION CONTRACT (§6.5/§9.1): generation throws are caught here.
  let ctx, genState;
  try {
    ctx = await orchestrator.prepare(prompt, currentState);             // CLARIFY + EXTEND (once); may THROW
    genState = await orchestrator.generateForIntent(ctx);              // GENERATE; may THROW (StructureEmptyError, merge parse)
  } catch (e) {
    return handleGenerationThrow(e, currentState, requestId);          // §6.5/§9.1.2 three-way classification
  }

  let state = genState, attempt = 0, bestSoFar = state;
  let result = await verifyRender(state, ctx, requestId, attempt);     // RENDER + VERIFY (attempt 0)
  const seen = new Set<string>([ msKey(result.errors) ]);             // ← SEED attempt-0 multiset BEFORE loop

  while (!result.ok && attempt < MAX_REPAIRS) {
    if (now()-t0 + 9000 > WALL_CLOCK_MS)      return degrade(bestSoFar, 'wall_clock', ctx);
    const prevKey = msKey(result.errors);
    const topErrors = result.errors.filter(e=>e.severity==='error').slice(0,8);
    const repair = await repairAgent.repair({ appState: state, errors: topErrors,
                                              originalPrompt: ctx.clarified.enrichedPrompt, attempt: attempt+1 });
    if (repair.unrepairable)                  return degrade(bestSoFar, 'unrepairable', ctx);
    attempt++; state = repair.appState;
    result = await verifyRender(state, ctx, requestId, attempt);
    bestSoFar = fewerErrors(result, state, bestSoFar);                // min severity-error count; ties → earliest
    if (result.ok) break;
    const curKey = msKey(result.errors);
    if (curKey === prevKey)                   return degrade(bestSoFar, 'no_progress', ctx);
    if (seen.has(curKey))                     return degrade(bestSoFar, 'oscillation', ctx);
    seen.add(curKey);
  }
  return result.ok ? toCritic(state, result, ctx)                     // → §6
                   : degrade(bestSoFar, 'budget_exhausted', ctx);
}
```

`verifyRender` renders with the frozen snapshot (`codeGen.generate(state, ctx.registrySnapshot)`) and calls `verifier.verify`, recording an `AttemptRecord`.

**Correctness trace within MAX_REPAIRS=2 (§6.0.8):**
- **No-progress (A→A):** seed `{A}`; repair1→A: `curKey(A)===prevKey(A)` → `no_progress` at attempt 1.
- **Oscillation (A→B→A) at the budget edge:** seed `{A}`; repair1→B (`B≠A`, `seen={A,B}`); repair2→A (`A≠B`, `seen.has(A)` **yes**) → `oscillation`. The pre-loop seed is what makes attempt-0's A catchable at attempt 2 — the off-by-one vPrev could not rule out.
- **Convergence (A→B→ok):** repair2→ok → `success`.
- **Slow divergence (A→B→C):** loop exits on `attempt<MAX_REPAIRS` false → `budget_exhausted`.

**`degrade()` never returns a state that failed VERIFY** (contract): it returns the **last code that PASSED verify**, or, if none ever passed, `bestSoFar` rendered + flagged `degraded:true` with residual `errors[]` surfaced — but `bestSoFar` is only ever surfaced as DEGRADED, never as SUCCESS, and **never** code from a failed-verify attempt the loop was mid-repairing. For create intents with no usable candidate, `bestSoFar` falls back to the deterministic `createDefaultState()` Welcome screen (valid by construction); for modify intents, to `ctx.baseState` (already verified). A synthetic `DEGRADE_WARNING { code:'D0', severity:'warning', source:'orchestrator' }` is attached. **`LoopResult` carries `finalState:'DEGRADED'` + `degradeReason`** so a degrade is never silently counted as success (§6.6 / §6.5).

### 4.3 api.ts persist policy + run() exception contract (the critical rewire, §6.5/§9.1.2)

Today api.ts (L37-44) does `process()` → `diffAppState` → `setState` → `generate`, all in one `try/catch` returning 500 (L52-55) — **no verification, can `setState` a failed state**. `process()` can throw from THREE sources (§6.5/§9.1): `BaseAgent.callFunction` (L38-39), **`enforceSingleScreen` empty-screens TypeError (structure-agent L284, §9.1)**, and `AppStateSchema.parse` in `merge` (L81). New `/api/generate`:

```ts
const result = await closedLoop.run(prompt, currentState);   // §6.5: never resolves with an unverified state/code
if (result.outcome === 'degrade-prior') {                    // generation threw, fell back to verified prior
  res.status(200).json({ sessionId, appState: result.appState, code: result.code,
                         degraded:true, finalState:'DEGRADED', degradeReason: result.degradeReason,
                         changelog: 'Your modification could not be applied and was reverted.' });
  return;                                                     // (no setState — prior already stored)
}
stateManager.setState(sessionId, result.appState);           // verified-ok OR known-good degrade only
const changelog = explainChanges(diffAppState(currentState, result.appState), result.appState.appName);
res.json({ sessionId, appState: result.appState, code: result.code, changelog,
           verified: result.verified, degraded: result.degraded, warnings: result.warnings,
           finalState: result.finalState,
           ...(result.fidelity && { fidelity: result.fidelity }),
           ...(result.degraded && { degradeReason: result.degradeReason }) });
```

**`run()` exception contract — three-way classification (§6.5/§9.1.2):** `run()` catches agent/structure/merge throws and classifies on error identity **and** on whether a prior verified state exists:

| Throw source | Phase | Prior state exists? | run() outcome |
|---|---|---|---|
| **`StructureEmptyError`** (new, structure L284 guard) | pre-merge | yes | **degrade-prior** (200): return `currentState` + its last-known-good code; `degradeReason:'structure_empty'` |
| **`StructureEmptyError`** | pre-merge | no (first request) | **500** — nothing verified to degrade to; surface `err.message` |
| `BaseAgent.callFunction` "no valid tool call" (L38-39) | pre-merge | yes / no | degrade-prior (200) if prior exists, else 500 |
| `AppStateSchema.parse` in merge (L81) | merge | yes / no | degrade-prior (200) if prior exists, else 500 |

```ts
function handleGenerationThrow(err, currentState, requestId) {
  const degradable = currentState != null;                   // prior produced by a past run() ⇒ already verified
  if (degradable) {                                          // re-render is deterministic & safe
    const reason = (err instanceof StructureEmptyError) ? 'structure_empty' : 'degrade-prior';
    return { outcome:'degrade-prior', finalState:'DEGRADED', degradeReason: reason,
             appState: currentState, code: codeGen.generate(currentState), verified:false, degraded:true };
  }
  throw err;                                                 // first-ever gen failed → route 500
}
```

Rationale (the explicit §9.1 decision): the empty-screens crash **degrades-to-prior when a prior AppState exists, and 500s only on the very first request of a session.** Degrade-to-prior returns the *previous* AppState, which by induction already passed VERIFY in its own generation, so re-emitting it is safe and honors "degrade never returns code that failed VERIFY." The first-request-no-prior case cannot degrade and must 500 — honest and rare. Defense in depth: the **`enforceSingleScreen` guard (Remedy 1, §9.1)** eliminates the crash class at the origin by throwing the typed `StructureEmptyError` instead of dereferencing `undefined`; `run()` (Remedy 2) decides degrade-vs-500. A synthesized placeholder screen is explicitly rejected — it would pass VERIFY and ship a blank app, a worse silent failure than an honest error.

Guarantees: (1) **no failed state is ever `setState`'d**; (2) `code` is rendered **once inside `run()`** from `result.appState` with the frozen snapshot (never re-rendered in the route, preserving cache identity); (3) `setState`'s `AppStateSchema.parse` is a cheap final invariant; (4) `finalState`/`degradeReason` surface degrade to the frontend.

**Import route `POST /api/state` (§9.2) — the sanitizer-free entry, async, three error channels.** This path does `AppStateSchema.parse` (L83) ONLY, bypassing **all** sanitizers (base-agent) AND `enforceSingleScreen` (structure-agent), so the guarantees the live path relies on (PascalCased names, single-screen, navigate-stripped, defaulted type/props, no `itemList`-typed itemFields) **do NOT hold** (Corollary B). The handler is **converted to `async`**, builds the snapshot+context inline (no Orchestrator on this path), renders first (deterministic), and splits the error response into **three channels** (the §9.2.3 decision — never collapse 422 into 400):

```ts
router.post('/state', async (req: Request, res: Response) => {
  // ── Channel 1: schema validation → 400 (unchanged client-malformed semantics) ──
  let validated: AppState;
  try { validated = AppStateSchema.parse(req.body.appState); }
  catch (err: any) { res.status(400).json({ error: err.message || '유효하지 않은 AppState입니다' }); return; }

  const sessionId = req.body.sessionId || randomUUID();
  const snapshot = widgetRegistry.cloneDefinitions();                 // RegistrySnapshot facade (§6.1), NOT a Map
  const ctx: VerifyContext = { source: 'import', registrySnapshot: snapshot,
                               registryVersion: snapshot.registryVersion };
  const code = codeGenerator.generate(validated, snapshot);           // render first; pure ⇒ cannot throw on schema-valid input

  // ── Channel 2: verifier INFRA failure (the validator itself threw) → 500 ──
  let result: AnalyzeResult;
  try { result = await staticValidator.verify(validated, code, ctx); }
  catch (err: any) { console.error('verify infra:', err); res.status(500).json({ error: '검증기 내부 오류' }); return; }

  // ── Channel 3: structural validation FAILED (valid JSON/schema, won't verify) → 422 (NEW) ──
  if (!result.ok) {
    res.status(422).json({ error: '가져온 AppState가 검증을 통과하지 못했습니다',
      validation: { errors: result.errors, warnings: result.warnings, source: result.source } });
    return;                                                           // do NOT persist / return failed code
  }

  stateManager.setState(sessionId, validated);                        // only after passing
  res.json({ sessionId, appState: validated, code, validation: { warnings: result.warnings } });
});
```

Decisions made explicit (§9.2.3): **(a) async conversion**; **(b) inline `RegistrySnapshot` + context** with `source:'import'` (load-bearing — lets telemetry and import-primary C-rules key off the path); **(c) three separated channels** — Zod parse failure stays **400** (client-malformed payload), a validator *throw* is **500** (a StaticValidator bug, e.g. an unexpected node shape), a validator *returning `ok:false`* is **422** (well-formed but structurally won't verify). 422 must never collapse into 400 — they mean different things to a tooling client. **Render before verify** because `verify(appState, code, ctx)` needs `code` and `generate` is pure (cannot throw on schema-valid input); any future C-rule needing a pre-render structural pass is gated inside `verify`, not the route. **Invariant P holds** (validator runs on the exact object codegen consumed). There is **no repair loop** on the import path — import is human-driven with no trusted prior, so we **422 with structured errors** rather than invoking RepairAgent or degrading. RepairAgent gating to the import path is a Layer-B-era follow-up.

### 4.4 RepairAgent patches, node-path, applyPatches

**RepairPatch + ops.**
```ts
export type RepairOp = 'set' | 'remove' | 'insert' | 'insert-create';
export interface RepairPatch { op: RepairOp; path: NodePath; value?: unknown; index?: number; }
```
`set` replaces (object key or array element) — **creating a missing object key is PERMITTED** (the common "add a missing action" case, §6.10); `remove` deletes a key/splices an element (requires `exists`); `insert` adds into an existing array at `index` (append if omitted); `insert-create` sets a missing array key to `[value]`. No move/copy.

**Node-path grammar:**
```
path     := segment ( '.' segment )*
segment  := key | index
key      := identifier            // object property: screens, props, title, action, type, …
index    := '[' DIGITS ']'        // array element
```
`props` is an ordinary object key; a list-item toggle resolves as `screens[0].body.children[2].props.itemBuilder.props.trailing.props.onToggle`.

**resolvePath set/create semantics (§6.10).** Traverse all but the last segment; a missing **intermediate** → `{error:'unresolvable'}` (patch dropped, logged). The **final** key may be absent: `exists=false` with `parent` resolvable is legal for `set` (`parent[key]=value`, creating the key) and `insert`/`insert-create`. `insert` index: `=== length` append, `< length` splice, `> length` unresolvable (no sparse arrays); a plain `insert` into a non-existent array key → unresolvable (use `set` then `insert`, or `insert-create`).

**editablePaths enforcement (blast-radius bound) — must cover repair targets, not just error sites (§6.10).** `editablePaths` is the closure (each path includes its subtree) of `⋃ error.location ∪ repairTargetPaths(error)`, where each C-rule declares the *additional* paths its sanctioned repair needs:
```
repairTargetPaths(C3b appBar-action) = [ appBar action path, screens[i].body ]            // body opened for the moved action
repairTargetPaths(C11 datePicker)    = [ node subtree, screens[i].screenState.variables ]  // coupled var edit (§6.11)
```
Without this widening, the recommended cross-node repairs (move appBar action to body; retype the coupled DateTime var) would be dropped as out-of-bounds.
```ts
function isWithinEditable(patchPath, editablePaths) {
  const p = tokenize(patchPath);
  return editablePaths.some(ep => { const e = tokenize(ep);
    return e.length <= p.length && e.every((seg,i)=>seg===p[i]); });
}
```

**applyPatches (deterministic):** `structuredClone(state)` (never mutate input); sort patches by path lexicographically, then same-array `remove`/`insert` by **descending index**; per patch: out-of-bounds → drop('out-of-bounds'), `resolvePath` error → drop('unresolvable'), else apply per op semantics above; finally `AppStateSchema.safeParse(clone)` — fail → return **ORIGINAL untouched**, `unrepairable=true` (never half-apply); success → `{ next: parsed.data, applied, dropped }`.

**`repair_appstate` function schema.**
```jsonc
{ "name":"repair_appstate",
  "description":"Given structural validation errors, return the minimal JSON patches that fix them. Touch only nodes named in the error locations. Do not rewrite unrelated parts.",
  "parameters":{ "type":"object","properties":{
    "patches":{"type":"array","items":{"type":"object","properties":{
      "op":{"type":"string","enum":["set","remove","insert","insert-create"]},
      "path":{"type":"string","description":"Dot/bracket path, e.g. screens[0].body.children[2].props.itemBuilder.props.trailing.props.onToggle"},
      "value":{"description":"New value for set/insert/insert-create; omit for remove"},
      "index":{"type":"integer","description":"Array position for insert; omit to append"}},
      "required":["op","path"]}},
    "repairNotes":{"type":"string"},
    "unrepairable":{"type":"boolean"}},

```

### 4.5 stageDefinition / commitDefinition split

`addDefinition` (which today `Map.set` **and** `persist()`s on every call, in the request hot path via `ensureWidgets`) is split so no request rewrites `registry.json`:

- **`stageDefinition(def)`** — in-memory `Map.set` only, **no `writeFileSync`**. Called by `ensureWidgets`. New widgets reach GENERATE/RENDER/VERIFY for *this* request via the frozen snapshot; disk untouched.
- **`commitDefinition(def)`** — `Map.set` + `persist()`. Called **only** by the registry-learning compile-gate (§2.5), **outside** the request hot path, after the candidate def rendered+verified clean (C7+C11). This is "compile-gate before persist."

Consequences: (a) `registryVersion` frozen per request; (b) `git diff --exit-code registry.json` clean after any eval run (only the offline learning-commit job writes); (c) "`registry.json` never rewritten mid-request" holds.

### 5.5 Shadow mode (Phase 2)

`VERIFY_MODE ∈ {off (default), shadow, enforce}`. In `shadow`: validator runs on every generated AppState in a `queueMicrotask` (non-blocking, all errors swallowed — a validator bug can never 500 a live request), logs **path-segmented** per-code histogram (live vs import) + shadow `ok` rate + `durationMs` p50/p95 + false-positive review + `cacheKey`/`fromCache`. Response unchanged. **Import-only C-classes (C9, C3-navigate, multi-screen, §6.0.2/§9.2.4) cannot appear in live shadow traffic** — the dashboard segments by path and those classes are validated by the synthetic corpus, not by waiting for impossible live traffic. Promotion to `enforce`: shadow false-positive rate ≈ 0 on negative controls + sampled traffic, and C11/datePicker + C3b + C1-dotted reliably caught.

### 5.6 CI (no Dart)

`tsx --test "test/**/*.test.ts"`; `VERIFY_MODE=off`, `DART_SERVICES_URL` unset (Layer-B tests skip via `test('...', { skip: !process.env.DART_SERVICES_URL })`). Final step `git diff --exit-code backend/golden backend/.../registry.json` enforces the determinism contract (safe — no request persists, §4.5). No Flutter/Dart toolchain at any step.

## 6. Critic + Eval

### 6.1 Placement

The Critic runs **after a passing VERIFY** (it judges *intent fidelity*, which the Verifier cannot):

```
VERIFY.ok==true → CRITIC → pass   → SUCCESS
                          → warn  → SUCCESS_WITH_WARNINGS (ship code + verdict)
                          → reloop→ RELOOP (cap 1) → GENERATE (must re-pass VERIFY) → re-judge
```

Hard rules: the Critic **never blocks code that passed VERIFY** (worst case = warn or one bounded reloop); it runs on the post-VERIFY AppState only; reloop and repair are **separate budgets**. A reloop re-enters GENERATE (`generateForIntent(ctx, verdict.reloopFeedback)`), must pass VERIFY again (failure → normal REPAIR/DEGRADE), then the Critic re-judges once — by §6.3 the re-judge yields only pass/warn, guaranteeing termination.

### 6.2 Interface

```ts
type CriticRecommendation = 'pass'|'warn'|'reloop';
interface CriticFeature { description: string; severity: 'core'|'minor'; evidence?: string; }
interface CriticVerdict {
  fidelityScore: number;            // 0..100
  recommendation: CriticRecommendation;
  missingFeatures: CriticFeature[]; extraFeatures: CriticFeature[];
  summary: string;                  // user-language, ships in changelog on warn
  reloopFeedback?: string;          // required iff recommendation==='reloop'
}
class CriticAgent extends BaseAgent { async critique(input: CriticInput): Promise<CriticVerdict>; }
```

Grounded with a deterministic **fact sheet** (screens, state vars, distinct action types via `collectActions`, distinct widget types, navigation) so it judges *intent*, not structure. Input: `originalPrompt`, `enrichedPrompt`, `intent`, fact sheet, truncated `code` head (~2k tokens). For `modifyDesign`, scores only visual fidelity.

### 6.3 Deterministic recommendation (model proposes, code decides)

```
coreMissing = missingFeatures.filter(f=>f.severity==='core').length
PASS=85, WARN=65
coreMissing===0 && score>=PASS              → 'pass'
coreMissing===0 && score>=WARN              → 'warn'
coreMissing>=1 && attempt===0               → 'reloop'
else                                         → 'warn'      // reloop budget spent
```

`extraFeatures` never force a reloop. Thresholds in `CRITIC_CONFIG` (eval-sweepable).

### 6.4 Cost control

Skip `modifyDesign` by default; cache verdict by `hash(originalPrompt + appStateHash + composite-cache-inputs)`; truncate `code`; a deterministic `quickFidelityGuard` pre-filter skips the LLM for trivially-satisfied simple apps (synthetic `pass`, `fidelityScore:-1`, source `skipped`); `MAX_CRITIC_RELOOPS=1`. Critic runs **in parallel** with Render+Verify (needs only `appState`+`originalPrompt`).

### 6.5 Feedback to API

`warn` → response gains `warnings: { summary, missingFeatures }`; `fidelity: { score, recommendation }` whenever the Critic ran. All optional/backward-compatible.

### 6.6 Eval harness

`backend/eval/`: `dataset/golden.jsonl`, `run-eval.ts`, `assertions.ts`, `llm-cache/` (replay), `baseline.json` (regression gate). Golden case schema: `expect: { minFidelity, mustContainActions, mustHaveStateVars, forbidWidgetTypes:["datePicker"], criticRecommendation, finalState }`. Covers single/multi-screen, CRUD, counter, form, design-only/structure-only modify, and **poison-trap** cases (datePicker / setValue / appBar-mutating-action / `{{x.y}}` / 7-char-hex / empty-screens-degrade).

**Assertion stack (fail-fast):** (1) `AppStateSchema.safeParse`; (2) production `Verifier.verify` — zero severity-error errors + deterministic `expect` checks; (3) **`finalState` discrimination:** every case expected to succeed asserts `finalState !== 'DEGRADED'` (a degraded Welcome screen is schema-valid but NOT a pass — prevents the regression gate being satisfied by mass-degradation); cases designed to degrade (poison-trap, oscillation, **empty-screens→`structure_empty`**) assert `finalState === 'DEGRADED'` with the expected `degradeReason`; (4) Critic (gated behind `--with-critic`, smoke subset in CI). `passRate` reported overall + per-tag; `staticPassRate` and **`degradeRate` (`degraded/total`)** reported separately.

**Fixture reuse:** Phase-0 corpus feeds `mode:"fixture"` cases (LLM-free, always-on CI gate — asserts `codeHash` to prove CodeGenerator stayed pure); `mode:"live"` exercises real agents (replay-cached, nightly). **Regression gate** (`eval:ci --gate`): hard-fail on any previously-passing case regressing, `staticPassRate` dropping, **or `degradeRate` rising** (no tolerance). `baseline.json` ratchets up only on deliberate promotion.

**Blocked on Layer B:** the harness gives schema-valid + structurally-clean + intent-faithful, **not compiles**. When RemoteAnalyzer registers behind the same `Verifier`, `assertions.ts` gains compile-grade signal with **no harness change** (it already calls `Verifier.verify`, source-agnostic).

## 7. Phase-5 Escape Hatch (Planner + customCode)

> **Phase fence.** Everything here is gated behind `FEATURE_PHASE5 = process.env.FLOWCRAFT_PHASE5==='1' && remoteAnalyzer.isAvailable()`. Multi-screen output and customCode expand the N1–N4 surface, so they are unreachable until Layer B backstops them. The pure-TS pieces (PlanValidator P1–P7, C12, C13) ship in Layer A now but dormant, so enabling Phase 5 is a flag flip + RemoteAnalyzer registration, not a refactor.

### 7.1 Planner

The MVP single-screen clamp lives **only** in `structure-agent.ts` (`enforceSingleScreen` L279-288 / `stripNavigateActions` L290-305); codegen already supports multi-screen. The Planner re-enables multi-screen by making navigation integrity a verified property (C9/C12) rather than a stripped-away capability — i.e. it lifts the exact clamp that makes C9/C3-navigate live-unreachable today (§6.0.2/§9.2.4).

A **PLAN** state inserts between CLARIFY and EXTEND, emitting an ordered `SegmentSpec[]` (cap `MAX_SEGMENTS=5`). Each segment carries `screenId/screenName/route/role/responsibility/requiredWidgets/navTargets`. The GENERATE→RENDER→VERIFY→REPAIR sub-loop runs **per segment** unchanged, then a **COMPOSE** + final composed VERIFY catches cross-screen errors.

`PlannerAgent.plan()` runs PlanValidator (P1–P7: unique ids/routes/names, resolvable nav targets, valid PascalCase, reachability, bottomNav consistency, segment cap) as the `validate` hook. Identifiers normalized deterministically (PascalCase, `/`-prefix, dedupe-suffix) to preserve the cache key.

Per-segment generation uses `StructureAgent.generateSegment(spec, plan)`: the single-screen clamp becomes a **scoped** instruction ("exactly one screen with this id/name/route; navigate ONLY to these screenIds"), and `enforceSegmentContract` overwrites identifiers from the spec (never trusts the LLM, and so cannot empty-screen-crash — the §9.1 guard still applies as a backstop) and runs a **scoped** `stripNavigateActions` deleting only `navigate` actions whose target ∉ `spec.navTargets`.

**Compose + final verify:** merge segment screens into one AppState (app-wide theme), `AppStateSchema.parse`, then composed VERIFY surfacing **C9** (nav integrity) and **C12** (duplicate `id`/`route`/class `name`). Composed failure → composed-level REPAIR (same caps/seeded guard). Unrepairable → DEGRADE to the **entry segment only** (already passed isolated verify, dangling edges stripped).

**Cross-screen state is deferred to Phase 5.1** (current `screenState` is per-screen; `Navigator.pushNamed` passes no arguments). v1 supports only *independent* screens connected by parameterless navigation. `SegmentSpec.ownedState` reserved but unused; cross-screen data binding is a warning, not generated.

### 7.2 customCode escape hatch

**Boundary:** the **declarative-safe-zone** (closed `WidgetNode`/`Action`/registry vocabulary — fully Layer-A-analyzable) vs. the **custom-code-zone** (a raw Dart fragment Layer A **cannot** analyze). customCode is the canonical reason Layer B exists.

```ts
// models/appstate.ts (additive)
CustomCodeSchema = z.object({
  dart: z.string(),
  interface: z.object({
    stateDeps: z.array(z.string()).default([]),    // MUST ⊆ enclosing screen's screenState
    imports: z.array(z.string()).default([]),
    returns: z.literal('Widget').default('Widget'),
    inputs: z.array(z.enum(['context','r'])).default(['context']),
  }),
});
// WidgetNode gains type==='customCode' → props.custom: CustomCodeSchema
```

The declared interface makes the opaque fragment governable: codegen confines it to `stateDeps`, hoists+dedupes `imports`, wraps it as a `Widget`-returning `Builder` closure. Layer A asserts exactly one thing — **C13** (`stateDeps ⊄ screen vars` → error); it cannot assert the Dart compiles.

`code-generator.ts` adds a `customCode` case **before** the registry fallthrough; when the gate is closed it emits `const SizedBox.shrink()` (mirroring the C5 behavior) and StaticValidator raises **C14** (warning).

**Double gate:** `allowCustomCode = FEATURE_PHASE5 && process.env.FLOWCRAFT_CUSTOMCODE==='1' && remoteAnalyzer.isAvailable()`. When on, the AppState is marked `requiresRemoteVerify=true`: the Orchestrator **must** route it to RemoteAnalyzer and may **not** mark SUCCESS on Layer A alone. Compile errors inside the fragment flow to RepairAgent as `source:'remote'`; unrepairable → DEGRADE replaces the node with `SizedBox.shrink()`, keeping the rest of the screen.

**Determinism trade-off:** CodeGenerator stays pure (the fragment is part of the AppState), so `generate()` remains deterministic — what weakens is the *verification authority* (a customCode-bearing AppState is "verified" only if RemoteAnalyzer ran; free-form Dart lowers cache hit rate). We refuse to ship it until Layer B exists to backstop it.

### 8.2 Residual risk register (Layer A only)

- **N1 nonexistent widgets** — mitigated by C11 + `KNOWN_FLUTTER_WIDGETS` (strictly closed, keyed on `def.dartWidget`, `DatePicker` excluded) + manual datePicker removal + the learning compile-gate. **Fully closed only by Layer B.** Allowlist additions human-vetted until Layer B can auto-prove a new ctor compiles.
- **N2 constructor signature mismatch** — partially caught by `widget-signatures.ts` (`closed:true` sigs). **Fully closed by Layer B.**
- **N3 Dart type mismatch / N4 Flutter API misuse** — **not decidable in Layer A**; blocked on Layer B. C8 covers value plausibility only (color via the exact `colorIsPlausible` mirror, §9.4); **C1-dotted member access is a *warned*, not closed, N3 surface** (the `_order.total` case's true compile verdict needs a front-end; this is precisely why its default severity is warning, §9.3); unknown icons are warned N4 surfaces.
- **Unsupported / undeclared / duplicate-method actions** — **closed in Layer A by C3b** (setValue/clearField, appBar mutating, gated-addItem, and same-name collisions all rejected until codegen declares a single matching handler).
- **Pre-merge generation crashes** — the `enforceSingleScreen` empty-screens crash class is **closed at the origin** by the §9.1 guard (typed throw) and **handled** by the §6.5/§9.1.2 run() classifier (degrade-prior or honest 500); it never yields an unverified code string.
- **Runtime correctness** (null-deref, overflow, async) — **not decidable by static analysis at all** (Layer B is `/analyze`, not execute); partially addressed by the Critic for intent but not runtime.

### 8.3 Key design decisions (with rationale)

1. **Wrap, don't rewrite `process()`** — three-function split hoists EXTEND out of the re-runnable region so the registry version is frozen per request.
2. **Determinism is load-bearing** — CodeGenerator is a pure function of `(state, registry-snapshot)`; `stableStringify` + the frozen composite cache key make verification content-addressable; powers the cache, the seeded oscillation guard, and reproducible eval. Color verdicts and codegen color output share the same two anchored regexes so they can never disagree (§9.4).
3. **A validator class may only fire on a symbol codegen actually emits, on the post-sanitize state** — C3b is membership-checked against the §6.0.5 oracle; C1-dotted/C8 pinned to verified emission (L547 / L1029-1031); the phantom `appBar.leading.action` is a non-site; fixtures are reachability-tagged live/import-only per §6.0.2/§9.2.4. False positives and false negatives are both fatal.
4. **The sanitize pipeline is the placement boundary, lives in `base-agent.ts`, and can throw before VERIFY** — the validator runs byte-for-byte on what codegen consumed (Corollary A); pre-merge throws (incl. the empty-screens crash, §9.1) are owned by the run() contract, not the C-rules; the import path bypasses sanitize entirely (Corollary B) and is the larger C-class exposure surface (three-channel, no repair).
5. **Validator reads the raw registry; persistence is gated separately** — C11 stays the front-line poison gate; `stageDefinition`/`commitDefinition` keep `registry.json` immutable mid-request.
6. **Two-tier strictness** — only the C11 allowlist is strictly closed; signatures/icons/colors degrade missing-curation to warning/repairable.
7. **Honesty over false precision in severity** — warnings never trigger repair (`ok` excludes warnings: W-leading, C8-color/icon-warn, **C1-dotted-warn**, C14); C1-dotted defaults to warning because Layer A cannot decide member-access compilation on a declared scalar (§9.3).
8. **Degrade never ships failing code, and is never silently a pass** — degrade returns the last verify-passing code, else `bestSoFar`/`baseState`/`createDefaultState()` flagged `DEGRADED` + `degradeReason`; pre-merge crashes degrade to the verified prior or 500; the eval gate discriminates success from degrade.
9. **Shared modules prevent validator/codegen drift** — `action-naming.ts` (C3b), `flex-rules.ts` (C6), `color-table.ts`/`known-icons.ts` (C8, §9.4), `node-path.ts` (validator + RepairAgent), and the dual lockstep test bind the validator to codegen by *importing* the same source. The phantom `HARDCODED_NODE_TYPES` repo identifier is purged.
10. **Layer B is registration-not-refactor** — the loop, guards, caps, degrade, RepairAgent, and eval are all `Verifier`-agnostic. Enabling Layer B = set `DART_SERVICES_URL`. Enabling Phase 5 = flag flip + that registration.
11. **Shadow before enforce, path-segmented** — StaticValidator gathers real-traffic false-positive data before blocking; import-only C-classes cannot appear in live traffic and are validated by the synthetic corpus.

# Appendix C — Residual data specifications (closes the 4 material gaps)

> These resolve the round-6 material gaps the architecture-critic loop structurally could not finish — they are **data enumeration + one signature**, not design. With these, Phases 0–2 are implementable with **no further design questions**. ## C.1 Identifier collision sets (C9 / C10)

**Scope first — where a *bare* (non-`_`-prefixed) identifier from user data reaches generated Dart:**

- **Screen names** → `class ${screen.name}` + the routes map. `sanitizeScreens` (L53–58) PascalCases and strips non-alphanumerics, so lowercase Dart keywords cannot survive verbatim — but two real collisions remain:
  - **Generator-emitted class names:** `MyApp`, `MainNavigation`, `_${name}State`. A screen named "My App" → `class MyApp` duplicates the root widget → duplicate-class compile error.
  - **Flutter/Material shadowing:** a screen named "Switch"/"Card"/"Container" → `class Switch` shadows the framework type used elsewhere in the same file.
- **State var names** → emitted as `_${name}` / `_${name}Controller` (L429–446). The `_` prefix makes Dart keywords *legal* identifiers (`_class` is valid) → **DART_RESERVED does NOT bite state vars; do not flag them.** The real risk is post-sanitize duplicate vars or a name that isn't a valid identifier tail (digit-leading, contains `$`).
- **Item field names** → always quoted map keys (`'field'`) → always safe; **never flag.**

```ts
// known-identifiers.ts
// Tier 1 — Dart reserved words (illegal as a bare identifier). Source: Dart language spec §17.1.
export const DART_RESERVED = new Set([
  'assert','break','case','catch','class','const','continue','default','do','else',
  'enum','extends','false','final','finally','for','if','in','is','new','null',
  'rethrow','return','super','switch','this','throw','true','try','var','void','while','with',
]);
// Tier 2 — built-in identifiers (illegal as TYPE/class names). Source: Dart spec §17.2.
export const DART_BUILTIN = new Set([
  'abstract','as','covariant','deferred','dynamic','export','external','factory','Function',
  'get','implements','import','interface','late','library','mixin','operator','part',
  'required','set','static','typedef',
]);
// Tier 3 — names the GENERATOR emits or Flutter defines, that a PascalCased screen name could shadow.
export const DART_CORE_COLLISIONS = new Set([
  // generator-emitted (code-generator.ts):
  'MyApp','MainNavigation',
  // Flutter/Material types referenced in generated output:
  'Scaffold','AppBar','Text','Column','Row','Container','Padding','SizedBox','Card','Center',
  'Expanded','ListView','ListTile','TextField','Checkbox','Switch','Divider','Icon','Image',
  'Slider','MaterialApp','ThemeData','Widget','State','StatelessWidget','StatefulWidget',
  'BuildContext','TextEditingController','EdgeInsets','Colors','Icons',
]);
```

**Application:**
- **C9-screen-name** (error): sanitized screen name ∈ (DART_RESERVED ∪ DART_BUILTIN ∪ DART_CORE_COLLISIONS), OR fails `/^[A-Za-z][A-Za-z0-9]*$/`, OR duplicates another screen's sanitized name.
- **C10-state-var** (error): `_${name}` fails `/^_[A-Za-z][A-Za-z0-9]*$/` (catches digit-leading / `$` / empty), OR two vars in a screen collide after the `_` prefix. **Do not consult DART_RESERVED for `_`-prefixed vars.**

**Also closes the minor empty-screens-crash gap:** the `StructureEmptyError` guard at structure-agent **L280 (before any deref)** must use the broad predicate `!Array.isArray(result.screens) || result.screens.length === 0` to cover both the missing-array and `screens:{}` shapes — not only the L284 single-deref the narrative pinned it to.

## C.4 C6 flex-rules signature fix

The design's `wouldUnwrap(child)` cannot express the rule: `unwrapExpandedIfNeeded` (L713–721) is **parent-agnostic**; parent gating lives at the **call sites** (the single-child slots, L737/751/764/781/926). Correct signature is `(parentType, childType)`:

```ts
// flex-rules.ts
const SINGLE_CHILD_UNWRAP_SLOTS = new Set(['container','padding','sizedBox','card','center']); // confirmed L737/751/764/781 call sites
export function expandedIsValid(parentType: string, childType: string): boolean {
  if (parentType === 'column' || parentType === 'row') return true;     // direct Flex child → legal
  if (SINGLE_CHILD_UNWRAP_SLOTS.has(parentType))        return true;     // generator auto-unwraps → never reaches Dart as Expanded
  return false;                                                          // e.g. Expanded directly under listView/listTile/expanded → C6 error
}
```
- **C6-expanded** (error): an `expanded`/`spacer` whose parent type ∉ {column,row} ∪ SINGLE_CHILD_UNWRAP_SLOTS.
- **One implementation verification (not a design question):** confirm the **L926 call site's host widget** during Phase 0; if it is a single-child slot beyond the five above, add it to the set. Flagged here so it isn't forgotten.

## C.5 Minor-gap one-liners
- **applyPatches ordering (S4):** sort by `(containingArrayPath, descending numeric index)` — group ops by their containing array first, then within each array apply removes/inserts in **descending integer index** order (parse the trailing `[n]` as an int). Do **not** lexicographically sort full NodePaths globally (that places `children[10]` before `children[2]`). Preserves the determinism the cache key depends on.
- **registryVersion invariant (S2):** add the one-liner — *"`registryVersion` hashes registry-defined definitions ONLY; the hardcoded widget set lives exclusively in `KNOWLEDGE_VERSION`. A change to HARDCODED_WIDGETS / the widget() switch must bump `KNOWLEDGE_VERSION`, never `registryVersion`."*
- **quickFidelityGuard predicate (S6):** bypass the LLM Critic (synthetic pass, `fidelityScore:-1`) only when ALL hold: single screen ∧ ≤1 state variable ∧ 0 registry/custom widgets ∧ `intent==='create'`. Anything richer goes to the LLM judge. (Phase 4, off the correctness path.)
